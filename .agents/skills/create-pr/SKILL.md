# PR 생성

변경 하나를 리뷰 가능한 PR로 만들고, 본문은 `.github/pull_request_template.md`에 맞춰 간결하게 작성한다. PR은 병합하지 않는다.

## 절차

1. **변경 확인:** 실제 저장소, 현재 브랜치, 원격, 기본 브랜치를 확인한다. 브랜치 전체 diff와 작업 트리를 검토해 의도한 변경만 포함됐는지 확인하고, 같은 브랜치의 기존 PR도 찾는다. 미커밋 변경이 PR에 필요하면 `commit` 스킬을 따른다. 관련 없는 변경을 스테이징하거나 커밋하지 않는다.
2. **제목과 본문:** 제목은 Conventional Commits 1.0.0 형식 `<type>[optional scope][!]: <description>`을 따른다. 제목은 짧고 한국어로 쓴다. 본문은 PR 템플릿의 항목을 채우고 실제 검증 결과를 포함한다. 해당 없는 항목은 이유와 함께 `해당 없음`으로 표시한다.
3. **생성:** 원격·기본 브랜치·인증을 확인하고, 기본 브랜치에서 PR을 만들지 않는다. 검사 실패 또는 미완성 변경이 있으면 준비 상태를 설명하고, 수정할지 draft로 열지 사용자에게 확인한다.
4. **보고:** PR URL, Conventional Commit 형식 제목, 대상 브랜치, 준비 상태와 실행한 검증을 알린다. 실패·생략한 검사와 남은 위험도 숨기지 않는다.

## 중단 조건

대상 브랜치·원격이 불분명하거나, 제안할 커밋이 없거나, diff에 설명되지 않은 변경이 있거나, GitHub 인증이 없으면 PR을 만들지 않는다. 사용자 변경을 버리거나 비밀값을 노출하지 말고 원인을 보고한다.
